# Module 3 - GradCafe PostgreSQL Data Analysis

## EN.605.256.81.SU26 - Modern Software Concepts in Python

## Overview

Module 3 extends the GradCafe data-processing workflow developed in Module 2 by loading the repaired and standardized applicant dataset into PostgreSQL and analyzing it using SQL.

The module demonstrates:

1. PostgreSQL database integration using psycopg
2. Loading standardized JSON data from Module 2
3. Data validation before database insertion
4. URL-based record de-duplication
5. Incremental database updates
6. SQL-based admissions analysis
7. Comparison of scraped and standardized fields
8. Dynamic presentation of SQL results using Flask
9. Background execution of the Module 2 data-refresh pipeline
10. Data-pull status monitoring

## PostgreSQL Data Loading

Run:

```powershell
python load_data.py
```

The loader:

- Connects to PostgreSQL using `DATABASE_URL`
- Creates or validates the `applicants` table
- Reads the standardized Module 2 JSON dataset
- Converts dates and numeric values to appropriate Python/PostgreSQL types
- Validates GPA and GRE-related values
- Uses applicant entry URLs for deterministic de-duplication
- Inserts new records
- Updates records whose URLs already exist
- Prevents duplicate applicant URLs
- Reports database validation statistics after loading

A successful current load processes:


This approach allows the database to be refreshed without creating duplicate applicant records.

## SQL Analysis

Run:

```powershell
python query_data.py
```

The script executes eleven SQL analyses against PostgreSQL.

### Q1 - Fall 2026 Entries

Counts applicant records for Fall 2026.

### Q2 - Percentage of International Students

Calculates the percentage of applicant records identified as international.

### Q3 - Average GPA and GRE Scores

Calculates:

- Average GPA
- Average GRE total score
- Average GRE Verbal score
- Average GRE Analytical Writing score

### Q4 - Average GPA of American Students in Fall 2026

Calculates the average GPA for American applicants reporting Fall 2026 admission results.

### Q5 - Percentage of Fall 2026 Acceptances

Calculates the acceptance percentage among Fall 2026 applicant records.

### Q6 - Average GPA of Fall 2026 Acceptances

Calculates the average GPA among accepted Fall 2026 applicants.

### Q7 - Johns Hopkins Masters Computer Science Entries

Counts Masters-level Computer Science entries associated with Johns Hopkins University using available scraped and standardized fields.

### Q8 - Selected 2026 Computer Science PhD Acceptances Using Scraped Fields

Searches the original scraped fields for accepted Computer Science PhD entries associated with selected universities.

### Q9 - Selected 2026 Computer Science PhD Acceptances Using Standardized Fields

Repeats the Q8 analysis using the standardized program and university fields generated during Module 2 processing.

This comparison demonstrates how standardized fields can improve matching when raw scraped values are inconsistent.

### Q10 - Top 10 Universities by Acceptance Count

Groups accepted applicant records by standardized university name and returns the ten universities with the largest number of reported acceptances.

### Q11 - Average GPA by Degree Type

Groups records by degree type and reports the average GPA and number of GPA-bearing entries for each degree category.

## Flask Application

Run:

```powershell
python app.py
```

Then open:

```text
http://127.0.0.1:5000
```

The application executes the SQL queries and displays the results through a Flask web interface.

Two actions are available:

### Update Analysis

Refreshes the webpage using the latest records currently stored in PostgreSQL.

### Pull Data

Starts the complete refresh workflow in a background thread.

The workflow runs:

```text
Module_2/scrape.py
        |
        v
Module_2/repair_applicant_data.py
        |
        v
Module_2/clean.py
        |
        v
Module_3/load_data.py
        |
        v
PostgreSQL
```

The Module 2 scraper includes protection for live-site anti-bot challenges. If reliable GradCafe data cannot be retrieved, the existing source dataset is preserved rather than overwritten with an invalid response.

Only one data-pull operation can run at a time. Additional Pull Data requests are rejected while a refresh is already running.

## Incremental Database Updates

The refresh process does not blindly append another copy of the dataset.

Applicant entry URLs are used as the de-duplication key. Existing URLs are updated and new URLs can be inserted.

This prevents repeated execution of the data pipeline from creating duplicate applicant records.

## Limitations

GradCafe data is anonymous and self-reported. Therefore, the dataset should not be interpreted as an authoritative representation of university admissions outcomes.

Potential limitations include:

- Self-selection bias
- Incomplete applicant reporting
- Missing values
- Incorrect or inconsistent user-entered values
- Variations in university and program naming
- Duplicate or malformed source records
- Limited ability to independently verify applicant information

The repair, standardization, validation, and de-duplication processes improve data consistency but do not eliminate the underlying limitations of the source data.

## Summary

Module 3 demonstrates an end-to-end data engineering and analysis workflow connecting web-collected admissions data, data repair and standardization, PostgreSQL persistence, SQL analysis, and a Flask presentation layer.

The workflow is designed to be repeatable while protecting existing data, preventing duplicate database records, validating numeric fields, and clearly separating raw scraped values from standardized values used for analysis.
